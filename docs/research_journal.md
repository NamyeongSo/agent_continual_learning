# 실험 기록장

실험 목적, 실행 경로, 재현 조건, 직접 작성한 노트, 산출물과 결론을 모으는 로컬 HTML 서버입니다.
Python 3.11 이상과 표준 라이브러리만 사용합니다. 외부 계정, 프런트엔드 빌드, 별도 데이터베이스 설치가 필요 없습니다.
기존 실행 상태 대시보드(`serve_experiment_dashboard.py`)와 독립적으로 실행됩니다.

실시간 모니터에는 학습 상태와 함께 **5 task CP 평가 · 공용 큐**가 표시됩니다.
CP별 train·val·test 진행률, 최대 100개 평가 작업, 동일 정책의 평가 생략을 확인할 수 있습니다.
등록·복원·최종 test 연결 방식은 [체크포인트 평가 큐](checkpoint_inference_queue.md)를 참고하세요.

## 실행

Exgentic 디렉터리에서 실행합니다.

```bash
uv run python scripts/utils/serve_research_journal.py
```

브라우저에서 <http://127.0.0.1:8878>에 접속합니다. 종료는 `Ctrl+C`입니다.
프로젝트 환경이 준비되어 있다면 `.venv/bin/python`으로도 실행할 수 있습니다.

```bash
.venv/bin/python scripts/utils/serve_research_journal.py \
  --port 8878 \
  --data-dir .experiment-journal \
  --allow-root /path/to/other/experiments
```

- `--port`: 기본값 `8878`.
- `--data-dir`: 기본값은 Exgentic의 `.experiment-journal/`. 기록 DB와 첨부 파일을 함께 보관합니다.
- `--allow-root`: 서버의 파일을 가져올 수 있는 추가 폴더. 여러 번 지정할 수 있습니다.
  기본적으로 Exgentic 아래의 파일은 허용합니다.
- 상대적인 **실험 경로**는 Exgentic 디렉터리를 기준으로 해석합니다.
  원격 서버의 경로는 로컬 경로처럼 읽지 못합니다. 해당 파일을 업로드하거나 접근 가능한 마운트를 지정하세요.

기본 설정은 `127.0.0.1`에서만 수신합니다. 다른 컴퓨터에서 사용하려면 SSH 포워딩을 사용할 수 있습니다.

```bash
ssh -N -L 8878:127.0.0.1:8878 user@research-server
```

포워딩한 컴퓨터에서도 <http://127.0.0.1:8878>로 접속합니다.

외부에서 진행 현황과 기록을 직접 조회하려면 수신 주소와 허용할 서버 주소를 명시합니다.

```bash
.venv/bin/python scripts/utils/serve_research_journal.py \
  --host 0.0.0.0 --allow-host 166.104.110.49 --port 8878 \
  --data-dir .experiment-journal
```

이 설정에서는 <http://166.104.110.49:8878/#live>로 실시간 모니터와 그래프를 조회할 수 있습니다.
외부 연결에는 쓰기 토큰을 제공하지 않으며 노트 수정·업로드·전체 백업·서버 파일 탐색은 로컬 접속에서
사용합니다. 조회 화면에는 외부 조회 상태를 표시하고 편집 버튼을 숨깁니다. 허용 호스트는
`--allow-host`로 각각 추가하며 wildcard는 허용하지 않습니다. 로컬 API와 SSH 포워딩의 편집 동작은 유지됩니다.

## 실시간 진행 모니터

자동 결과 비교표와 LaTeX 갱신은 [결과표 안내](live_results_table.md)를 참고하세요.

<http://127.0.0.1:8878/#live>에서 ACE·PREMiSE·GEPA·SkillOpt의 각 benchmark/seed 실행을 추적합니다.

각 실행 카드에는 온라인 Train, Val, 최종 Test 점수가 크게 표시됩니다. ACE·PREMiSE의
온라인 Train은 각 task에서 업데이트 전 첫 actor/parent의 공식 점수 평균이고, GEPA·SkillOpt는
첫 학습 노출의 이진 성공률입니다. PREMiSE의 여러 parent·candidate·replay를 중복 집계하지 않습니다.
GEPA·SkillOpt의 Val은 최근 후보 평가이며, ACE·PREMiSE는 최근 CP의 Val 평가를 표시합니다.
최종 Test와 CP Test는 이름으로 구분됩니다. 집계 task 수와 전체 완료 여부를 함께 표시하며,
실행 중에는 완료분 평균만 계산합니다. 인프라 오류와 미측정 결과는 0점으로 바꾸지 않고,
실제로 측정된 0점은 그대로 포함합니다. CP 표에도 각 split 점수를 표시합니다.
기본 첫 화면이며 왼쪽 **실시간 모니터**로도 열 수 있습니다.

**5 task CP 평가 · 공용 큐**에서 각 방법·벤치마크·seed 토글을 열면 checkpoint별 점수 그래프와
상세 표가 나옵니다. x축은 학습 task 수 기준 checkpoint, y축은 0–100% 점수이며,
Train (CP 평가)·Offline-val·Test (CP 평가)를 각각 켜고 끌 수 있습니다.
평가가 진행 중이어도 현재까지 측정된 task의 평균을 빈 원으로 표시하고, 전체 완료는 채운 원으로,
동일 정책의 평가 재사용은 마름모로 표시합니다. 점 위에 마우스를 올리거나 키보드로 선택하면
정확한 점수·측정 건수·오류 제외 건수를 확인할 수 있습니다. 미측정 값은 0으로 채우지 않으며,
CP마다 측정 task 수가 다를 수 있습니다. CP Train은 고정 정책 재평가이고 학습 과정 Online과는 별도입니다.
그래프는 5초마다 갱신되고 토글 열림 상태와 split 선택은 유지됩니다. AppWorld는 세 split 모두 TGC입니다.

- 전체 실행·대기·완료·오류 수, 전체 학습과 Test 처리량을 5초마다 갱신합니다. 예정된 작업도 전체 분모에 포함합니다.
- 각 run에 학습·Test bar를 따로 표시하고, GEPA/SkillOpt의 초기·후보 validation과 현재 batch 진행률도 표시합니다.
- 방법·벤치마크·상태·seed로 필터링하며, 실행 묶음을 접거나 해당 실험 기록으로 이동할 수 있습니다.
- 각 실험 묶음·개별 실행·메인 테이블·CP 평가·Policy shift의 **삭제** 버튼으로 모니터에서 항목을 숨길 수 있습니다.
  메인 테이블·CP 평가·Policy shift 영역 전체도 숨길 수 있습니다. 삭제 직후 **실행 취소**, 상단 **숨긴 항목**에서
  개별 복원 또는 전체 복원을 제공합니다. 표시 설정은 브라우저에 저장되어 새로고침·자동 갱신 후에도 유지되고
  같은 주소의 다른 탭에도 반영됩니다. 다른 브라우저·접속 주소와는 별개입니다. 외부 조회 화면에서도 사용할 수 있습니다.
  숨긴 실험은 상단 실험 수와 학습·Test 진행 합계에서도 제외되며, 메인 테이블의 결과 집계는 독립적으로 유지됩니다.
  실행 프로세스·결과 파일·실험 기록은 삭제하지 않습니다.
- ACE는 curator 완료 근거와 연속 task prefix, PREMiSE는 완료 cursor, GEPA/SkillOpt는 최초 노출 기록을 읽습니다.
  GEPA/SkillOpt가 마지막 train task에 노출됐어도 optimizer 종료 근거가 없으면 계속 실행 중으로 표시합니다.
- Test는 결과 파일이 있는 task의 처리율입니다. 성공률과 별개이며 공식 실패 0도 처리에 포함합니다.
  인프라 실행 오류는 별도 집계하며, 오류가 남은 run을 정상 완료로 표시하지 않습니다.
- 대체된 queue는 제외하고 종료한 PID를 실행 중으로 세지 않습니다. 연결 지연 시 마지막 데이터를 유지하고 재연결합니다.

`outputs/*/launch_manifest.json`과 등록된 실험 경로의 queue를 자동 발견합니다.
학습 파일·환경·모델을 수정하거나 호출하지 않는 읽기 전용 `/api/live-progress` API이며 진행 신호가 없는
과거 기록은 기존 기록장 기능을 사용합니다. 개별 실험 기록에도 해당 queue의 요약 bar가 표시됩니다.
갱신은 진행 현황 영역만 바꾸므로 미저장 노트와 입력 중인 진행 기록을 보존합니다.

ACE Context Proposal의 Train-only 실험은 실험 폴더의 `ace_study_monitor.json`으로 연결합니다.
`kind`는 `ace_context_proposal_train_only_v1`, `journal_id`는 기존 실험 기록 ID로 지정합니다.
`initial_metrics_file`은 실험 폴더 안의 초기 성능 JSON 경로입니다. 초기 추론, Reflection → Update,
후보 평가, Context 학습, 최종 Train 평가의 진행률과 학습 전 PCT·TGC·pass@5·pass⁵를 표시합니다.
최종 결과가 저장되면 seed별 Train 점수의 평균±표준편차도 표시하며, 전체 모니터와 해당 실험 상세
페이지에서 5초마다 갱신됩니다. 이 조회는 실험 실행이나 모델 호출을 수행하지 않습니다.

## 기본 흐름

1. **실험 등록**: 제목과 목적을 입력합니다. 계획 중인 실험은 경로와 결과를 나중에 채워도 됩니다.
2. **재현 조건**: 방법, 벤치마크, 모델, seed, split 파일/해시, 예산, 코드 커밋과 실행 명령을 남깁니다.
3. **실험 노트**: 실험 상세 페이지에서 자유롭게 작성하고 **노트 저장**을 누릅니다.
   노트는 계속 수정할 수 있습니다. 날짜별로 남길 내용은 **진행 기록 추가**를 사용합니다.
   진행 기록의 시각은 자동으로 저장되고 브라우저의 현지 시간대로 표시됩니다.
4. **결과 지표**: 수치, 단위, split, 근거 파일/집계 방식을 입력합니다.
   `0`, `72.4 ± 1.2` 모두 유효합니다. 값을 입력하지 않은 지표는 결과로 간주하지 않습니다.
5. **산출물 첨부**: 파일을 끌어 놓거나 선택합니다. 서버에 있는 파일은 경로로 가져올 수 있습니다.
   저장된 실험 폴더에서 산출물을 찾아 개별적으로 가져오는 것도 가능합니다.
6. **해석 정리**: 핵심 결론, 한계와 다음 할 일을 기록하고 상태를 갱신합니다.
7. **비교와 공유**: 목록에서 실험을 선택해 비교하거나 내보냅니다.

일반 노트와 진행 기록은 줄바꿈을 보존하는 일반 텍스트로 표시됩니다.
노트, 진행 기록, 파일 이름과 캡션도 목록 검색에 포함됩니다.
목록의 여러 검색어는 모두 일치하는 실험을 찾습니다. 방법과 태그로 추가 필터링할 수 있습니다.
동시에 편집한 기록은 버전 충돌을 감지하며, 오래된 편집 창으로 최근 노트를 덮어쓰지 않습니다.

ADD-only와 ADD + UPDATE 비교를 위한 작성 템플릿도 제공합니다.
템플릿은 목적과 비교 조건만 채우며, 실제 실행이나 결과를 생성하지 않습니다.

## 산출물 보관

- 업로드 또는 경로 가져오기 시 기록장 폴더에 **사본**을 만들고 SHA-256을 기록합니다.
  원본이 나중에 바뀌거나 이동해도 당시 사본을 확인할 수 있습니다.
- 파일당 최대 `64 MiB`입니다. 이미지와 SVG, CSV/TSV, PDF, 텍스트 등의 미리보기를 제공합니다.
  그 밖의 파일도 첨부하고 다운로드할 수 있습니다.
- 표 미리보기는 최대 100행, 30열, 128 KiB이며 큰 셀은 줄입니다. 전체 파일은 보존합니다.
- 폴더 검색은 하위 3단계, 최대 500파일/1,500폴더로 제한합니다.
  생략된 파일도 정확한 경로로 가져올 수 있습니다.
- 허용 경로 밖, 숨김 파일, 가상환경 및 키 파일은 경로 가져오기 대상에서 제외합니다.
- 첨부 해제는 원본을 지우지 않습니다. 보관함으로 옮긴 실험도 노트와 첨부 파일을 유지합니다.

## 논문 작성과 진척 공유

| 내보내기 | 용도 |
| --- | --- |
| 공유용 HTML | 노트, 진행 기록, 재현 조건, 결론과 산출물을 포함한 독립 문서. 이미지와 표를 표시하고 다른 첨부 파일도 다운로드할 수 있습니다. 서버 없이 열거나 브라우저 인쇄로 PDF를 만들 수 있습니다. |
| Markdown ZIP | `report.md`와 상대 경로로 연결된 `artifacts/`를 함께 보관합니다. 압축을 해제한 구조를 유지하세요. |
| CSV | 실험 정보와 지표별 한 행. 값이 0인 결과도 유지하며 스프레드시트 수식 실행을 막도록 문자열을 처리합니다. |
| LaTeX | 선택한 실험의 지표 비교 `tabular`. 한글은 적절한 글꼴/패키지를 사용하는 XeLaTeX/LuaLaTeX 환경이 필요합니다. |

비교는 **지표명 + split + 단위**가 모두 같은 값만 같은 행에 놓습니다.
없는 결과를 0으로 채우거나 서로 다른 단위를 변환하지 않습니다.
재현 조건의 차이는 화면에서 노란색으로 표시합니다. 평균·표준편차·유의성을 자동으로 추정하지 않습니다.

공유용 HTML은 첨부 파일을 내장하므로 포함된 원본 파일 크기의 합을 `128 MiB`로 제한합니다.
큰 산출물은 실험을 나누어 내보내거나 Markdown ZIP 또는 전체 백업을 이용하세요.

## 저장과 백업

기본 폴더 구조:

```text
.experiment-journal/
  journal.sqlite3
  artifacts/
```

`.experiment-journal/`는 Git에서 제외됩니다. `--data-dir`를 다른 위치로 지정하면 그 위치의 Git 제외 설정은 별도로 관리하세요.
코드만 복사하면 실험 기록은 이동하지 않습니다. DB와 첨부 파일을 함께 백업하세요.

화면 왼쪽 아래 **저장 위치 · 백업 → 전체 백업 ZIP 다운로드**를 사용합니다.
서버가 동작하는 중에도 SQLite의 일관된 스냅샷과 해당 스냅샷이 참조하는 첨부 파일을 함께 보관합니다.
백업에는 보관함 실험과 사람이 읽을 수 있는 `experiments.json`도 포함됩니다.

복원 방법:

1. 서버를 종료합니다.
2. ZIP을 **새로운 빈 폴더**에 압축 해제합니다.
3. 해당 폴더를 데이터 경로로 지정해 실행합니다.

```bash
uv run python scripts/utils/serve_research_journal.py --data-dir /path/to/restored-journal
```

백업 ZIP과 공유 보고서에는 실험 노트, 로컬 경로, 선택한 산출물이 들어갑니다.
공유할 실험을 선택하고 그 내용을 검토한 뒤 전달하세요.

## 개발 검증

```bash
uv run pytest tests/scripts/test_research_journal.py -q
uv run ruff check scripts/research_journal scripts/utils/serve_research_journal.py tests/scripts/test_research_journal.py
```

서버 코드는 `scripts/research_journal/`, 정적 화면은 그 아래 `static/`에 있습니다.
API는 같은 서버에서만 사용하는 쓰기 토큰과 Host/Origin 검사를 사용합니다.
HTTP API를 이용하는 로컬 자동화는 `/api/info`에서 토큰을 읽어 `X-Journal-Token`으로 전달할 수 있습니다.

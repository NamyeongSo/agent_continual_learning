# Repository Guidelines

## Project Structure & Module Organization

This directory is the Exgentic component bundled with AgentStream. Framework code lives in `src/exgentic/`: `agents/` contains agent methods, `benchmarks/` contains benchmark adapters, `core/` runs sessions, and `adapters/runners/` manages isolated execution. Put reusable experiments in `scripts/` (for example, `scripts/ace/`), usage examples in `examples/`, and longer explanations in `docs/`. Tests mirror these areas under `tests/`; recorded replay fixtures live in `tests/benchmarks/recordings/`. Images and other documentation assets are in `misc/assets/`.

## Build, Test, and Development Commands

Run commands from this directory unless noted otherwise:

```bash
uv sync --frozen                       # Install the locked project environment
uv run exgentic list benchmarks       # Check the CLI and available benchmarks
uv run exgentic install --benchmark appworld  # Install one benchmark's dependencies/data
uv run pytest tests/ --ignore=tests/integrations --ignore=tests/adapters/runners
uv run ruff check src tests scripts    # Lint Python changes
```

For isolated-runner changes, also run `uv run pytest tests/adapters/runners -v -p no:faulthandler`. From the Sico repository root, run `pre-commit run --config labs/AgentStream/exgentic/.pre-commit-config.yaml --all-files --show-diff-on-failure`. See `DEVELOPMENT.md` and `docs/TEAM_SETUP.md` for benchmark-specific setup.

## Coding Style & Naming Conventions

Use Python 3.11+, four spaces, double-quoted strings, and a 120-character line limit (`ruff.toml`). Use `snake_case` for modules/functions, `PascalCase` for classes, and descriptive benchmark or method names. Add the Apache-2.0 SPDX header to new Python source files. Keep benchmark-specific dependencies inside their isolated environments, not the core package.

## Testing Guidelines

Use pytest. Name files `test_*.py` and test functions `test_*`; place tests near the corresponding area under `tests/`. Add focused regression tests for fixes, then run the relevant suite. Runner, Docker, and live-model tests may require external services; document any skipped checks. No repository-wide coverage threshold is specified.

## Commit & Pull Request Guidelines

Follow Conventional Commits, as in `fix(labs): ...` and `feat(labs): ...`. Keep commits focused. PRs should explain the change, link relevant issues, include test results, and identify skipped checks. Update the root `CHANGELOG.md` for user-facing changes when contributing through Sico; follow its root `CONTRIBUTING.md` for review and security reporting.

## Security & Experiment Outputs

Do not commit credentials, SSH keys, benchmark installations, `.env`, virtual environments, or experiment outputs. Keep private Docker access details in the ignored local handoff file, and verify new sensitive paths with `git check-ignore` before sharing a branch.
